# UniBlueprint public website audit (2026-09-26)

Scope: the public marketing site (`src/pages/*` served through `src/App.jsx`, excluding `app/`), with emphasis on the pages a signed-out visitor actually lands on: Home, Pricing, Free Trial, Foundation/Elevation/Lifestyle Blueprint, How It Works, About, Join, Contact, the legal pages, and the global Navbar/Footer/TrialBanner/CookieBanner that render on every page.

Method: every in-scope file was read against the repository's current tip on `claude/website-build-ouh47r` (commit `93712be9`, "Merge app fix batch 2: safety and misleading-content fixes") — **not** this worktree's own stale branch head, which sits at commit `5674ae0e` (2026-09-04) and predates both the CRO commit (`3b3b4573`) and a sitemap-dedupe fix (`2b2f2fee`) that this task's brief assumes are already in place. All line numbers below are against `93712be9`; re-check them if this worktree is later rebased onto that branch. No live Supabase queries were run in this session — DB/Edge Function state is taken from the mobile app audit (`docs/audits/2026-09-24-app-core-findings.md`/`-app-builders-findings.md`, read from the same branch), which checked the live project directly on 2026-09-24.

This is a **redo** of an audit cut short on 2026-09-24; there was no partial report to build on, so this is a full fresh pass.

**Totals: 21 findings. 4 P0, 9 P1, 8 P2.** Plus 6 decisions needed.

## 0. The headline: two of the site's core commercial promises can't currently be kept

Cross-referencing the mobile app audit's section 0 ("the backend the app needs isn't live"):

1. **Paying on the website can charge real money and deliver nothing.** `CheckoutButton` (`src/components/pricing/CheckoutButton.jsx:32-38`) calls the `create-checkout-session` Edge Function and redirects to real Stripe Checkout whenever `VITE_STRIPE_PUBLISHABLE_KEY` is configured (`src/lib/stripe.js:9-14`). `create-checkout-session` **is** deployed live. But `stripe-webhook` — the function that turns a completed Stripe payment into a `subscriptions` row and flips a user to Pro — is **not** deployed (app audit section 0). `public/_redirects:4-15` still carries a `TODO: Configure stripe-webhook Edge Function URL` with no live redirect rule. So the moment the Stripe key is set in Netlify, a real visitor can pay €6.99–€49.99 and never receive Pro.
2. **Foundation Blueprint's central promise — a reviewed CV/cover letter/etc. delivered in 48 hours or same-day — cannot be fulfilled at all.** The 9 Foundation tables and the `submit_document_for_review` RPC don't exist live (app audit section 0: "Every Foundation builder fails at submit"). `FoundationBlueprintPage.jsx` and `HowItWorksPage.jsx` (below) advertise this pipeline in specific, confident detail.

Neither of these is a website bug in the sense of a typo — they're the site accurately describing a product that, per this session's own app audit, doesn't work yet end to end. Until #53 (migration drift) is resolved and the functions are deployed, either the CTAs need to be gated off or the copy needs to stop promising a working pipeline.

## 2. P1 — broken, wrong, or a real consumer-protection risk

- **Elevation Blueprint markets coaches as "Verified" with no real vetting behind it, on the site's own highest-visibility Elevation page.** "Verified Coaches across Ireland" (`src/pages/ElevationBlueprintPage.jsx:361`) and "Verified Uni Coaches" (meta description, `:316`) is the same claim the app audit found is backed by a hardcoded `verified = true` default with no real vetting recorded anywhere (app audit `VerifiedBadge.jsx:16`). This is the marketing-copy half of that same problem, on the page a visitor reads before ever opening the app. → Either build a real verification step before using the word "Verified" here, or soften the copy to something true today (e.g. "Coaches across Ireland").
- **The "50% off" free-trial pricing is reference pricing that, per the live DB, has never actually been charged to anyone** (0 subscriptions, 0 submissions as of the app audit's live check). `PricingPage.jsx` (`PRICING_ROWS`, lines 26-47) and `FreeTrialPage.jsx` (`CALCULATOR_SERVICES`, lines 8-14) both show a struck-through "standard" price next to a "trial" price framed as 50% off — the exact EU Consumer Rights (Omnibus) issue the app audit flagged for Foundation pricing (app fix plan 2e), now confirmed to also be the construction used on the site's actual Pricing page, its highest-conversion page. → See Decision D2 below; this needs a business/legal call, not a silent copy edit.
- **Foundation Blueprint and How It Works disagree with each other on Premium turnaround.** Foundation Blueprint says Premium is "Same day" (`FoundationBlueprintPage.jsx:28, 190, 858`: "48hr Standard · Same day Premium"), while How It Works says Premium is "24 hours" (`HowItWorksPage.jsx:29`: "Premium: 24 hours and first in the queue"). A visitor who reads both pages gets two different promises. → Pick one turnaround time and use it on both pages (and in the DB deadline the app audit already flagged as a mismatched 24h column, app fix plan 2c).
- **`/contributors` is a fully public route with no auth gate, linked from the Footer's "Join" column and the Navbar's "Join the Team" dropdown, but is missing from `vite.config.ts`'s sitemap `ROUTES` array** — so it silently drops out of the real, build-time-generated `sitemap.xml` the same way the six routes fixed on 2026-09-22 did. Verified the earlier dedupe fix (commit `2b2f2fee`) is intact at the current tip — no duplicate entries in `ROUTES` today — but this is a fresh instance of the same class of bug. `src/App.jsx:101` (`<Route path="/contributors" ...>`, no `ProtectedRoute` wrapper) vs `vite.config.ts:15-40` (no `/contributors` entry). → Add `"/contributors"` to `ROUTES`.
- **The Home and Download pages' meta descriptions, and the About page's founder story, still say "Launching September 2026"** — `src/pages/HomePage.jsx:657, 659`, `src/pages/DownloadPage.jsx:322`, `src/pages/AboutPage.jsx:491` ("September 2026 is launch."). Today is 2026-09-26; this session already fixed the identical phrase on the app's own About screen ("Launching September 2026" → "Launched"). The website has the same stale future-tense copy, unfixed. → Update to past tense, or to whatever the real launch-status wording should now be (see Decision D1 — this interacts with whether the app is actually on the stores yet).
- **"A note from founder" is missing "the"** (`src/pages/AboutPage.jsx:461`) — the exact same typo the app audit flagged for the app's AboutScreen and which is still unfixed there too. Fix both together if there's a shared copy source; otherwise fix each.
- Both `CookiesPage.jsx` and `AccessibilityPage.jsx` **never name the operating company at all** — no "Ltd"/"Limited", no CRO number, unlike Terms, Privacy and (nominally) Refund Policy. For two policies that exist specifically for compliance reasons, that's a gap the CRO batch should have closed too. → Add the same one-line entity statement used on Terms/Privacy, or at minimum a "see Terms for our company details" cross-link.
- `RefundPolicyPage.jsx:33`, `CookiesPage.jsx:60` and `AccessibilityPage.jsx:31` all still say **"Last updated: June 2026"**, while Terms and Privacy were bumped to "September 2026" in the CRO batch. Refund Policy's own content *was* edited this session (the VAT section, line 118) — so its "Last updated" date is now actively wrong, not just stale. → Bump Refund Policy's date to September 2026 to match its real edit history; Cookies/Accessibility can stay if genuinely untouched, but confirm that's true.
- **Trading/copy-trading content is on the public, unauthenticated Elevation Blueprint page.** "Dinero Trading Group" with services "Low-Risk Copier" and "10X Challenge" (`ElevationBlueprintPage.jsx:51`) is visible to any visitor, including the 5th/6th-year (15–18-year-old) segment the site markets to elsewhere (Course Compass, CAO content) — the same age-appropriateness question the app audit raised as Decision D5 for the app's Investment tab, except here it's on the open web with no age gate at all. → See Decision D4.

## 3. P2 — polish and cleanup

- `index.html:39-56` still runs a dead, second GA4-loading script with the literal placeholder `GA_ID = 'GA_MEASUREMENT_ID'`, left over from before `CookieBanner.jsx:4` was wired up with the real ID (`G-YKY97WYWQD`, fixed in commit `dac684bf`). It never fires (the ID is invalid) but it's confusing dead code sitting next to the real, working implementation. → Delete the inline script block in `index.html`; `CookieBanner.jsx` already does this correctly, gated on cookie consent.
- `TrialBanner.jsx` (shown at the top of every public page) is pure text with a dismiss button and **no link at all** — "50% OFF all services, free trial. Your Blueprint. Half the price." (`:43`) isn't wrapped in anything clickable. A visitor who wants to act on it has to go find Pricing themselves. → Wrap the text (or add a small "See pricing" link) pointing to `/pricing` or `/free-trial`.
- `FreeTrialPage.jsx` uses raw emoji as feature icons (🏛 📚 💚 👤, lines 18/23/28/33) where every other part of the site (Navbar, Footer, Foundation/Elevation pages) uses `lucide-react` icons consistently. Same inconsistency the app audit flagged for the app's Campus Connect tiles. → Swap for Lucide icons (e.g. `Landmark`, `BookOpen`, `HeartHandshake`, `User`).
- `uniblueprintoperations@gmail.com` is the public contact address on at least 8 files (Footer, Contact, Terms, Privacy, Refund, Cookies, Accessibility, Partner Portal) — already tracked as a known issue in the app fix plan (section 5), just noting the website carries the bulk of the public-facing instances and should move in the same batch once the domain mailbox is confirmed live.
- The hand-maintained `public/sitemap.xml` committed to the repo (25 URLs) is stale against the real, build-time-generated one from `vite.config.ts`'s `ROUTES` (33 entries) — missing `/free-trial`, `/budgeting`, `/ad-board`, `/course-compass`, `/behind-the-blueprint`, and has `/contributors` (which, per the P1 item above, isn't actually in `ROUTES` and so won't survive a real build). Low risk since the file that ships is the generated one, but confusing for anyone who reads the repo's `public/sitemap.xml` and assumes it's current.
- The blog hasn't published anything since **2026-06-01** (`src/data/blogPosts.js:187, 210` — the two most recent posts share that date), roughly four months ago, while `sitemap.xml` declares `changefreq: weekly` for `/blog` and both the Navbar's "How It Works"-adjacent traffic and Footer treat it as a live content pillar. A dormant blog undercuts both the freshness signal to search engines and the "we're an active platform" impression for a visitor who clicks through post-launch.
- No missing `alt` text was found on any of the site's five raw `<img>` tags (`BehindTheBlueprintPage.jsx:116`, `AboutPage.jsx:203`, `ElevationBlueprintPage.jsx:172`, `PageLoader.jsx:17`) — worth recording as verified-fine rather than re-flagging in a future pass.
- Security headers (`public/_headers`) and the SPA fallback (`public/_redirects:1-2`) were both already fixed by an earlier session and remain intact — no regression found here.
